# 数据与隐私

## 录音和识别

录音由快捷键触发，支持按住、切换和锁定三种操作。屏幕底部有录音状态，macOS 也会显示麦克风指示。App 不主动把录音保存为音频文件；这不是对系统内存、崩溃转储或第三方服务保存策略的保证。

“隐私优先”使用 macOS 的 `DictationTranscriber` 和本机文字规则，应用不会把音频或文字发送到 OpenRouter。初次准备中文识别资源可能需要联网下载。

“效果优先”及自定义云端模式使用 `https://openrouter.ai/api/v1`：

| 请求 | 发送的内容 |
| --- | --- |
| 云端识别 | 分段的 WAV 音频及中文语言标识；同时请求两个识别模型 |
| 云端整理 | 当前识别文字、本次口述前文的最后 300 个字符、当前应用名、整理指令 |
| 保存 Key 后测试连接 | 固定的短测试文字 |

两个识别请求竞争返回结果，不是失败后才调用备用。取消较慢请求不代表服务端尚未收到音频，也不保证不计费。OpenRouter 和上游服务商能够处理请求正文；它们的保存与处理规则不由 SayType 控制。

只把识别改成本机，不代表整理也在本机。想避免上述云端请求，请选择“隐私优先”；点击“测试连接”仍会主动发起云端请求。

## 本机保存什么

| 位置 | 内容 | 清理方式 |
| --- | --- | --- |
| `~/Library/Application Support/SayType/history.json` | 原始识别文字、整理后文字、时间、应用名、引擎和状态 | 历史窗口 → 清空全部；关闭保存只影响新记录 |
| `~/Library/Logs/SayType/` | 事件、耗时、字数、应用信息、快捷键事件和错误类别 | 退出 App 后可自行删除；当前没有自动轮转 |
| macOS 钥匙串，服务名 `io.github.legendkyouma-glitch.saytype.openrouter` | 在设置中保存的 API Key | 设置 → OpenRouter Key → 清除 |
| macOS 偏好设置域 `io.github.legendkyouma-glitch.saytype` | 模式、快捷键、引导状态等 | 卸载时可删除偏好设置 |

历史最多保存 500 条，**加载及保存时**清理超过 30 天的记录并写回文件。App 关闭期间不会定时清理磁盘，关闭历史保存也不会立即删除旧记录。历史是明文 JSON，不是加密数据库。

正常运行日志没有专门记录口述正文或 Key 的字段；云端错误也不保存服务商响应正文。日志仍包含应用标识、应用路径和部分按键事件等元数据，分享前请检查。命令行自检会直接打印识别文字，不能当作脱敏日志。

### 可选的配置文件

除了钥匙串，应用还支持 `local.config.json`：从源码运行时可放在仓库根目录，安装版可放在 `~/Library/Application Support/SayType/`。格式见仓库的 `local.config.example.json`。这是明文文件，已被仓库的 `.gitignore` 排除。

读取优先级为：钥匙串 → 源码运行位置对应的配置文件 → Application Support 中的配置文件。设置里的“清除”只删除钥匙串项；配置文件需要自己删除。不要把配置文件、Key 或个人历史附在 Issue 中。

## 输入焦点和剪贴板

辅助功能权限用于响应快捷键、确定输入焦点、读写目标输入框及核对替换位置。它不采集整张屏幕，也不会自动按回车发送消息。

不支持直接写入的输入框会使用剪贴板粘贴。App 尝试恢复原剪贴板；需要手动粘贴时，结果会保留在剪贴板里。其他剪贴板管理软件、目标应用或系统同步功能仍可能读取这些文字。

App 会尝试阻止向安全输入框写入，并在焦点变化时退回手动粘贴，但无法保证所有应用都提供足够信息。云端迟到替换在只支持粘贴的应用中也无法逐字核对旧内容。

## 卸载

需要删除 Key 和文字历史时，先在 App 内清除它们，再退出 SayType 并删除 `SayType.app`。如使用过配置文件，也要单独删除。

可选清理项：删除上表中的 SayType 数据目录、日志目录和偏好设置；在“系统设置 → 隐私与安全性”中移除 SayType 的辅助功能权限。删除 App 本身不会自动移除这些数据。
